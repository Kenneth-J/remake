# Rebuild mode: from a remake to your own codebase

The default remake runs the original's own HTML, CSS and scripts. That's why it matches: nothing was redrawn. Some users want more: a React or Next.js codebase they can grow. Rebuild mode gets there without losing the match, because the score keeps running the whole time.

Only do this when the user asks for it.

## The rule

The score is a lock. Rebuild one section at a time, re-score after each, and never move on while a screen that passed before is failing now.

## Steps

1. **Keep the remake as the reference.** Leave `site/` as it is. Build the new app in `app/` (or a framework folder) and serve it with the framework's dev server. To score it, put its build output into `site/` on a branch, or point `remake score` at a copy of the project whose `site/` holds the build.
2. **Set up the frame first.** Copy the original's stylesheets into the app unchanged and in the same order (base, components, utilities, then site rules). Fonts, colours, breakpoints and spacing come with them. Rewriting the CSS into a new system on day one is the fastest way to lose the match.
3. **Convert markup section by section.** Turn each section's HTML into a component (`class` → `className`, inline `style` strings → objects, numeric attributes as numbers, `for` → `htmlFor`, self-closing void tags). Keep every wrapper element: scripts and CSS select on them.
4. **Port behaviour, don't reinvent it.** Read the original source first: `remake/sources/` when the site publishes source maps, otherwise the scripts in `site/`. Port module by module (smooth scroll, text effects, sliders, WebGL), keeping the order things start in. A "similar" animation library or a hand-written approximation is the most common reason a rebuild stops matching.
5. **Score after each section.** Fix before moving on.
6. **Swap content last**, through a content file your components read, the same slots as `remake/content.json`.

## What tends to break

- Hydration mismatches when markup is generated by scripts after load: render those parts on the client only.
- Script start order: the original may expect the loader, scroller and canvas to exist before components start. Start them in the same order.
- Staggered animations that miss their final frame: draw the end state on complete.
- CSS cascade order changes when a framework splits stylesheets per component: keep one global stylesheet in the original order until the end.
